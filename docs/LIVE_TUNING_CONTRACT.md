# 실시간 차량 설정 규격과 확장 준비

2026-09-29. 화면 `/tv`는 피트 `/pit`의 `dashboard.css`를 공유한다.
검정 배경, 청록색 강조, 패널, 숫자 표시, 상태 색상과 반응형 구성을 통일했다.
페이지를 열거나 값을 고르는 것만으로는 명령이 전송되지 않는다.

## 강도와 상한 — 사용자가 확인한 의미

- **좌우 구동력 배분 강도**: TV 또는 전자식 차동(ED)이 계산한 좌우 출력 차이에
  곱하는 비율. 100%는 그대로, 50%는 절반, 0%는 좌우 출력 명령을 균등하게 만든다.
- **강도 상한**: 요청 강도의 최대 허용값.
  `목표 강도 = 차동 허용 ? min(요청 강도, 상한) : 0`.
  요청 80% / 상한 50% → 목표 50%, 요청 30% / 상한 50% → 목표 30%.
- 실제 적용값은 STM의 변화율 제한을 거쳐 목표값으로 이동한다.
- 기계식 LSD 잠김, 동일 RPM 강제, 모터 총출력/10kW 제한, PID 게인 변경과 다르다.
- 버튼을 누르는 동안만 원격값을 유지한다. 해제/숨김/포커스 상실/연결 상실은
  원격 유지를 종료한다. 마지막 값의 영구 저장은 지원하지 않는다.
- 현재 연결 보드는 명령 만료 후 강도/상한 100%/100% 복귀가 관찰되었다.
  이 값은 모든 STM의 보편 규칙이 아니며, 펌웨어 변경 시 다시 확인해야 한다.
- ACK는 명령 수신 확인이다. 명령 만료 후에도 마지막 수신 번호가 남을 수 있으므로
  화면은 원격 유지 상태와 실제 적용값을 별도로 표시한다.

## 공통 항목 정의

원본은 `protocol/tuning_parameters.json` 한 곳이다. 프런트엔드는 서버의
`GET /api/control/catalog`에서 항목 정보와 현재 지원 상태를 가져온다.
ID, key, 표시명, 단위, 고정소수점 배율, 범위/간격, 접근 상태, 텔레메트리 키를 정의한다.

| ID | 항목 | 현재 지원 |
|---|---|---|
| 1 / 2 / 3 | 배분 강도 / 상한 / 허용 | 기존 LIVE_TV 명령으로 변경 |
| 101 / 102 / 103 | PID Kp / Ki / Kd | 보드 보고값 조회만 |
| 201 | 강도 변화율 | 조회만; 현재 UART 쓰기 명령 없음 |
| 202 | 좌우 차동 출력 상한 | 향후 항목 |
| 301 | 총출력 요청 예산 | 향후 항목 |

미지원 항목에는 임의 조정 범위를 부여하지 않는다. PID와 출력 예산의 배율 1000은
향후 값 표현을 예약한 것으로, 현재 쓰기 지원이나 적정 게인 범위를 뜻하지 않는다.
PID 표시값은 검증된 `_tuning_values`에서만 읽으며 오프라인에는 `—`로 표시한다.
값 0과 미수신을 구별한다. BMS 설정 항목은 이번 범위에 포함하지 않는다.

`capability_source=server_legacy_contract_not_device_negotiation`은 서버가 알고 있는
기존 규격이라는 뜻이다. 새 장치 능력 협상이나 PID 쓰기 지원을 감지한 결과가 아니다.

## 서버 요청과 현재 전송 방식

기존 로컬 접근 제한을 적용하는 `POST /api/control`에 다음 형태를 추가했다.

```json
{
  "type": "parameter_update",
  "schema_version": 1,
  "request_id": 19,
  "persistence": "volatile_lease",
  "values": {"strength_pct": 35, "limit_pct": 60, "tv_enable": true}
}
```

버전 1은 세 값을 한 묶음으로 검증한다. request_id는 기존 wire에 맞춰 0~255 정수다.
강도/상한은 정수 0~100 및 5 단위, 허용은 JSON boolean만 받는다.
부분 변경, 알 수 없는 항목, PID 쓰기, 범위 초과, NaN, 버전 불일치, 영구 저장 요청은
전달 전에 거부한다. 하나라도 잘못된 경우 일부 값만 적용하지 않는다.

검증된 요청은 기존 `live_tv` 메시지로 변환되어 기존 서버 권한/오류/deadman 검사를
그대로 거친다. 기존 클라이언트의 `live_tv` 요청도 호환 유지한다.
알 수 없는 command type을 기존 pit_config로 해석하던 경로는 명시적으로 거부한다.

## ESP / STM 펌웨어 준비

`scripts/generate_tuning_contract.py`가 다음 세 프로젝트의
`djy_tuning_parameters.h`를 동일하게 생성한다.

- `firmware/esp32_ev_gateway/include`
- `firmware/stm32_rear_binary/Core/Inc`
- `firmware/stm32_rear_uart/Core/Inc`

공통 ID/배율, 버전, 상태 코드, 검증 함수와 확장용 내부 `DjyTuningUpdate` 타입을 포함한다.
이 구조체는 전송용 packed frame이 아니며, 새 UART 메시지를 활성화하지 않는다.
미지원 PID/예약 ID 검증은 `DJY_TUNING_UNSUPPORTED`를 반환한다.
기존 LIVE_TV 수신 검증과 ESP JSON 수신 검증은 이 공통 검증 함수를 사용한다.
9바이트 wire 형식, CRC8, 강도 의미, 제어 루프의 복귀 동작은 바꾸지 않는다.

준비본은 `C:/Users/ljh/telemetry-tools/esp-tuning-contract-ascii` 및
`esp-tuning-contract-highrate`에 별도로 빌드 완료했다. 네 플래시 이미지의 factory 이미지 일치와
SHA-256을 확인했고, 각 폴더에 `manifest.json`, `upload.ps1`, `README.md`를 저장했다.
보드에는 업로드하지 않았다.
ASCII 준비본은 기존 로컬 UDP 목적지 `172.20.10.14`를 유지한다. 고속 준비본은 기존 HTTPS relay와
로컬 UDP 비활성 설정을 유지하므로 배포 전 STM 통신 규격과 네트워크 설정을 확인해야 한다.
현재 확인된 STM은 115200 ASCII 방식이다.
이번 화면/API는 기존 보드 명령과 호환되어 보드 재업로드 없이 사용할 수 있다.
STM 보드는 수정/업로드하지 않는다. STM C 헤더는 호스트 C 컴파일로 검증하며,
이 PC에는 ARM 전체 빌드용 컴파일러가 확인되지 않아 STM 전체 펌웨어 빌드는 별도다.

## PID 등 실제 쓰기 추가 시 완료해야 할 항목

1. 대상 STM 버전과 차량별 허용 범위·단위·변경 가능 상태를 확정한다.
2. PID Kp/Ki/Kd는 한 번에 검증/적용하는 그룹으로 취급하고, 적분 상태·필터 상태 처리와
   적용 시점을 제어 루프에 연결한다. 단순 전역변수 덮어쓰기로 끝내지 않는다.
3. 기존 wire와 충돌하지 않는 별도 버전/메시지, 장치 지원 정보, 요청 ID, 적용 응답 및
   실제 읽기값을 구현한다. 재전송·중복·순서 역전·재부팅·부분 손실을 검증한다.
4. 실시간 유효기간과 RAM 유지/기본값 복귀/영구 저장 정책을 항목별로 정의한다.
   지금의 임시 강도 명령 규칙을 PID 저장 규칙으로 자동 재사용하지 않는다.
5. ESP와 서버는 장치 지원이 확인될 때만 새 명령을 전달하고, ACK 및 읽기값이
   확인된 경우에만 화면에서 적용 완료로 표시한다.
6. 위 구현과 검증이 끝난 항목만 공통 정의와 화면에서 쓰기 가능으로 전환한다.
